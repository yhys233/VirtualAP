# DESIGN.md

[English](DESIGN.md) | [简体中文](DESIGN.zh-CN.md) | [繁體中文](DESIGN.zh-TW.md) | [Русский](DESIGN.ru.md) | [Français](DESIGN.fr.md) | [Deutsch](DESIGN.de.md) | [日本語](DESIGN.ja.md) | [한국어](DESIGN.ko.md)

Визуальный язык Android-приложения VirtualAP, это язык дизайна Droidspaces,
перенесённый вместе с компонентами, которые его реализуют. Backend это скрипт оболочки без
UI, поэтому ничего из этого не относится к `backend/`.

Компоненты идут первыми, значения вторыми: инвентарь переиспользования в
[CONTRIBUTING.ru.md](./CONTRIBUTING.ru.md) перечисляет то, что существует, а этот файл нужен для случая, когда
там ничто не покрывает вашу потребность. Никогда не хардкодьте hex-цвет, размер в sp или радиус, который вы
подобрали на глаз.

## Как выглядит приложение и почему

В этом приложении ничто не приподнято. Глубина выражается шагом цвета поверхности на один
уровень вверх и рисованием границы 1dp; если вы тянетесь к тени, вы вышли из дизайна.
`Surface` это примитив: кнопки это кликабельные Surface, а не Material `Button`, и
диалоги это `Dialog { Surface { } }`, а не `AlertDialog`. Компоненты Material не запрещены,
но они приходят со своими умолчаниями высоты и радиуса, и их нужно обосновывать.

Цвет выводится, никогда не задаётся буквально. `ui/theme/Theme.kt` смешивает полную схему из трёх
цветов палитры или берёт схему Material You целиком. Динамический цвет включён по умолчанию,
резервные палитры поставляются для старых устройств и для пользователей, которые его отключают, а AMOLED сводит
каждую поверхность к чёрному, поэтому хардкод `Color(0xFF...)` ломает все четыре пути сразу.

Границы и тонировка несут состояние, заливки остаются тихими. Работающая точка доступа не зелёная карточка;
это обычная карточка с тонированной кнопкой и акцентной границей.

## Цвет

Роли берутся из `MaterialTheme.colorScheme`. Сама схема строится в `ui/theme/Theme.kt`
из палитр в `ui/theme/Color.kt`, единственных двух файлах, которые называют цвет буквально.

| Поверхность | Роль |
| --- | --- |
| Фон экрана | `background` |
| Карточка на фоне | `surfaceContainer` |
| Карточка или чип внутри другой поверхности, и интерактивные строки настроек | `surfaceContainerHigh` |
| Оболочка диалога и нижней шторки | `surfaceContainer` |

| Текст | Роль |
| --- | --- |
| Основной | `onSurface` |
| Вторичный, вспомогательный, метаданные | `onSurfaceVariant` при альфе `0.7f` |
| Третичный, намеренно тихий | `onSurfaceVariant` при альфе `0.6f` |
| Отключённое содержимое | `onSurface` при альфе `0.38f` |
| Заливка отключённого контейнера | `onSurface` при альфе `0.12f` |

Границы всегда 1dp. Меняется альфа:

| Граница | Цвет |
| --- | --- |
| Карточка | `outlineVariant` при `0.35f` |
| Оболочка диалога | `outlineVariant` при `0.4f` |
| Обёртка панели действий и другие вложенные поверхности | `outlineVariant` при `0.2f` |
| Разделитель (`HorizontalDivider`) | `outlineVariant` при `0.3f` |
| Текстовое поле, без фокуса | `outlineVariant` при `0.5f` |
| Текстовое поле, в фокусе | `primary` при `0.8f` |
| Тонированная кнопка, в тон своему акценту | роль акцента при `0.2f` |

### Что означают цвета

Жизненный цикл точки доступа одинаков по всему приложению, и новые состояния должны присоединяться к нему,
а не изобретать параллельный словарь.

| Состояние | Акцент |
| --- | --- |
| Работает, здоров, действие запуска | `primary` |
| Остановлен, сбой, разрушительное, действие остановки | `error` |
| Действие перезапуска | `secondary` |
| В процессе, перезапуск, загрузка | `tertiary` |
| Простой, неизвестно, сообщать нечего | `onSurfaceVariant` при `0.6f` |
| Отключено | заливка `onSurface` при `0.08f`, акцент `outlineVariant` |

Тонированная кнопка берёт заливку из соответствующей роли контейнера при альфе `0.4f`, например
`primaryContainer.copy(alpha = 0.4f)` для запуска и `errorContainer.copy(alpha = 0.4f)` для остановки,
с границей 1dp цвета акцента при `0.2f`.

Консоль окрашивает строку `[WARN]` в `tertiary`, а строку `[ERROR]` в `error`, по уровню,
который `classifyLine` читает из тега; backend выдаёт простой текст, без escape-кодов.

## Типографика

Шкала это собственная шкала Material 3, `Typography()` в `ui/theme/Type.kt`. Используйте именованные стили и
передавайте начертание на месте: заголовок это `titleLarge` с `FontWeight.Bold`, заголовок карточки
`titleMedium` SemiBold. Нигде в приложении нет переопределения `fontSize`.

Текст UI это `FontFamily.Default`. Всё, что произвела машина, строка лога, значение конфигурации,
путь, это JetBrains Mono, импортированный из `ui/theme/Type.kt`. Не объявляйте локальное семейство
шрифтов.

| Элемент | Стиль |
| --- | --- |
| Заголовок экрана в `TopAppBar` | `titleLarge`, Bold |
| Заголовок диалога | `titleLarge`, Bold, по левому краю |
| Заголовок карточки | `titleMedium`, SemiBold |
| Заголовок раздела внутри экрана | `titleSmall`, Bold, `primary` |
| Надпись кнопки | `labelLarge`, SemiBold |
| Основной текст в диалоге | `bodyMedium` |
| Вспомогательный текст, метаданные, подзаголовки | `bodySmall` с `onSurfaceVariant` при `0.7f` |
| Надпись чипа статуса | `labelSmall`, Black, `letterSpacing = 0.5.sp`, заглавными |
| Машинный вывод | `bodySmall` со шрифтом JetBrains Mono |

## Отступы

Шкала это **4, 8, 12, 16, 20, 24, 32**. Ничего больше. Если промежутку кажется, что нужно 14, ему
нужно 12 или 16.

| Интервал | Значение |
| --- | --- |
| Край экрана, списки и дашборды | 16 по горизонтали |
| Край экрана, мастер и потоки настройки | 24 по горизонтали |
| Между карточками в списке | 16 |
| Между блоками внутри карточки | 12 |
| Внутренние отступы карточки | 16 |
| Внутренние отступы диалога | 24 |
| Иконка до своей надписи, чип до чипа | 8 |
| Плотные строки метаданных | 4 |

Панели вкладок нет. Главный экран находится над `PrimaryActionBottomBar` внутри `Scaffold`,
поэтому измеренная высота панели приходит как внутренний отступ Scaffold, и список расчищает её
без того, чтобы кто-то вписывал число расчистки. Оставьте так: панель, которая не является `bottomBar`
у Scaffold, требует литерала, а литерал дрейфует.

### Заголовки карточек совпадают по линии

У карточки активной сети нет заголовка: её первая строка это имя сети слева и
чип статуса справа, над разделителем, при минимальной высоте `CardHeaderHeight` и
внутри `CardContentPadding`, оба из `ui/component/CardMetrics.kt`. Высота 48dp,
потому что строка содержит кнопку-иконку QR Wi-Fi, а 48dp это нижняя граница для касания.

Карточка, у которой всё же есть заголовок с чипом, берёт те же два значения, поэтому её разделитель и
чип держат ту же линию, что и здесь. Если вы их меняете, вы двигаете каждый заголовок карточки в
приложении, и это и есть задуманное направление.

## Панель действий

Ряд связанных действий находится внутри тонированной обёртки:

```kotlin
Surface(
    shape = RoundedCornerShape(12.dp),                    // wrapper
    color = MaterialTheme.colorScheme.surfaceContainerHigh,
    border = BorderStroke(1.dp, MaterialTheme.colorScheme.outlineVariant.copy(alpha = 0.2f))
) {
    Row(Modifier.padding(4.dp), horizontalArrangement = Arrangement.spacedBy(4.dp)) {
        Surface(
            modifier = Modifier.weight(1f).height(48.dp),
            shape = RoundedCornerShape(16.dp),            // button, larger than the wrapper
            color = accentContainer.copy(alpha = 0.4f),
            border = BorderStroke(1.dp, accent.copy(alpha = 0.2f))
        ) { /* icon + labelLarge SemiBold */ }
    }
}
```

Кнопки круглее коробки, в которой сидят, и это дизайн: отступ 4dp плюс
больший внутренний радиус заставляют кнопки читаться как выступающие над обёрткой, а не
вложенные в неё заподлицо. Совпадение двух радиусов сплющивает эффект.

Переключатель Interface или Container на главном экране (`SegmentedSelector` в
`ui/screen/MainScreen.kt`) это эта геометрия, использованная как селектор: выбранный сегмент получает
тонированную заливку и акцентную границу, другой остаётся прозрачным. Строка Clear и Copy над
консолью лога (`LogActionRow`) это не то: это голая строка из двух кнопок 38dp без
обёртки.

## Диалоги

Каждый диалог это `DsDialog`, которому принадлежит и компоновка, и рамка: `Surface` на всю ширину
внутри отступов 24dp, ограниченный высотой экрана минус эти отступы, и колонка с отступами 24dp,
тело которой прокручивается. Граница берётся из `LocalConfiguration`, а не из окна, поэтому диалог, открытый
через поворот, измеряется по живой конфигурации. Вызывающие не задают ширину, свои
отступы или свою прокрутку, и никогда не передают `wrapContentHeight()`; то, что относится к конкретному диалогу, едет
на `modifier`, `imePadding()` для текстового поля или ограничение `heightIn(max = ...)`.

Заголовок это `titleLarge` Bold, по левому краю, и это первое, что идёт в содержимом.

## Действия диалога

About, информационная страница, закрывается из своего заголовка через `DialogCloseButton`. Диалог с выбором,
выбор языка, заканчивается `DialogFooterRow`: две кнопки 48dp равного веса при радиусе 16,
тихий тональный отказ и заполненное подтверждение, однострочные надписи с усечением. Он идёт в
слот `footer` у `DsDialog`, измеряемый до прокручиваемого тела, чтобы альбомная ориентация не сжала его. Первый
разрушительный диалог копирует `error` подтверждение из Droidspaces.

## Иконки и цели касания

| Использование | Размер |
| --- | --- |
| Ведущая иконка в карточке или строке списка | 20 |
| Действие панели инструментов, иконка внутри кнопки | 18 |
| В строке с текстом `bodySmall` | 16 |
| Заголовок диалога | 24 |
| Глиф героя настройки | 96, внутри героя 240 |
| Точка статуса | 6 |

Всё, по чему можно нажать, не меньше **48dp**. Это нижняя граница доступности, а не стилевое предпочтение,
и это единственное правило в этом файле, которое дизайн-аргумент не может отменить.

## Выравнивание

Строки это `Alignment.CenterVertically`.

Заголовки карточек и заголовки диалогов всегда по левому краю. Строка карточки, которая соединяет заголовок с
элементом управления, использует `Arrangement.SpaceBetween`.

Центрированный текст зарезервирован для состояний на весь экран: пустые списки, загрузка, герои настройки. Если содержимое
центрировано внутри карточки, это, вероятно, ошибка.

## Движение и загрузка

Спиннеры берутся из `LoadingIndicator` с `LoadingSize`, никогда голый `.size(n.dp)` на
индикаторе прогресса. Загрузка на весь экран это `FullScreenLoading`; `LoadingSize.Hero` (144)
единственный загрузчик героя потока настройки. Тайминги анимации берутся из `AnimationUtils`; смены состояния героя
используют `MaterialTheme.motionScheme`, который тема выставляет в `MotionScheme.expressive()`.

### Поток настройки

Пейджер приветствия, проверка root и установщик backend делят одну геометрию, которая живёт
в `ui/component/SetupHero.kt`. `SetupPage` это скелет под Scaffold: строка 40dp
сверху (счётчик страниц в пейджере приветствия, пустая в остальных местах), слот рамки, который центрирует
своё содержимое или прокручивается, когда окно слишком короткое, и строка 44dp снизу (точки страниц).
Каждый экран держит обе строки, чтобы рамка и кнопка никогда не двигались между экранами.
`SetupFrame` это рамка: блок героя 240dp, затем заголовок и текст в фиксированном текстовом
блоке. `SetupHero` это герой экрана, который что-то делает, `MaterialShapes.Cookie12Sided` 240dp
в `primaryContainer` или `errorContainer`, держащий загрузчик или
глиф 96dp, и между состояниями меняются только его цвет и содержимое. Герой пейджера приветствия
это вместо этого собственная `Shape`, мягкий всплеск, который успокаивается в печенье, клевер и солнце, пока
страницы скользят над ним. `SetupActionBar` это одна кнопка. Постройте новый экран настройки из них,
и герой, заголовок и кнопка встанут на те же строки, что у остальных.

## Когда правило не подходит

Иногда не подойдёт, и ответ не в том, чтобы тихо взять другое число.

Скажите об этом в PR и оставьте комментарий на месте, объясняющий, что даёт отступление, как
делают решённые исключения ниже. Незадокументированное отступление это дрейф, и следующий участник
его «исправит». Задокументированное это решение, и оно выживает.

## Решённые исключения

Рассмотрены и намеренно оставлены как есть. Не открывайте их заново без причины, которую упускает
исходная.

- **Пластина QR это `Color.White`** в шторке QR Wi-Fi, и `QrCodeGenerator.encode` рисует
  чёрные модули на белом. Сканеру нужен контраст, который предполагает спецификация; пластина с темой под
  тёмной палитрой читается как сломанный код.
- **Карточка статуса отвечает на касание** (`ActiveNetworkCard` в `ui/screen/MainScreen.kt`), хотя
  она ничего не открывает. Это карточка, которую пользователь трогает, чтобы проверить, живое ли приложение, поэтому она даёт рябь и сбрасывает
  фокус поля вместо того, чтобы лежать мёртвой под пальцем. Цена в том, что TalkBack читает её как один
  узел с действием.
- **Шторка QR Wi-Fi, шторка устройств и шторка логов** в
  `ui/screen/MainScreen.kt`, и шторки списка устройств в `ui/component/DeviceList.kt`,
  остаются Material `ModalBottomSheet`, а не
  `Dialog { Surface { } }`. Все они это содержимое, закрываемое перетаскиванием, которое
  принадлежит нижнему краю, а шторка логов блокирует закрытие жестом, пока выполняется команда,
  чтобы шторка не оставила позади затемнение, поедающее касания. Их оболочка это
  `surfaceContainer` с верхними углами 24dp, в соответствии с таблицей форм.
- **Кнопка потока настройки** (`SetupActionBar` в `ui/component/SetupHero.kt`) это полная пилюля
  без поверхности панели и без разделителя, а не кнопка панели 20dp. Она стоит одна на фоне
  под героем, а не над прокручиваемым содержимым. Её отключённые цвета остаются равны включённым:
  она отключена только пока идёт проверка или установка, и серость на этот момент
  читается как мерцание.
- **Слабые альфы заливки 0.03 и 0.06** в `LogActionRow` остаются необщими. Они невидимы
  в изоляции, и сведение их к общему значению означало бы изобрести токен для того, что никто
  не видит.
